  ANSWERING COMMON INTERVIEW QUESTIONS
═══════════════════════════════════════════════════════════════════════════

Q: "Why use federated learning for NIDS?"
A: "Enterprise networks need intrusion detection without centralizing 
   sensitive traffic data due to privacy regulations (GDPR, HIPAA). Federated 
   learning enables model training across multiple network segments while each 
   segment maintains data locality and privacy."

Q: "How does the FedAvg algorithm work?"
A: "FedAvg performs weighted averaging of model parameters across clients, 
   proportional to their data sizes. After each round, the server aggregates 
   weights: W_global = Σ(|D_i|/|D| × W_i). This ensures clients with more 
   data have proportionally more influence on the global model."

Q: "What's the role of SMOTE in this project?"
A: "CIC-IDS 2017 has severe class imbalance (BENIGN is ~99.8%). SMOTE 
   synthetically oversamples minority classes (attacks), creating balanced 
   training data. This prevents the model from biasing toward majority class 
   while maintaining test set imbalance to reflect real-world scenarios."

Q: "How did you handle 2.8M records in preprocessing?"
A: "Implemented efficient pandas-based pipeline with vectorized operations. 
   For demo, sampled 1-5% to enable fast iteration. Production version uses 
   streaming processing with batch normalization. Feature selection 
   (78→50 features) reduced dimensionality without accuracy loss."

Q: "What metrics did you optimize for?"
A: "Balanced F1-score and ROC-AUC since precision/recall trade-off matters 
   in security. False positives waste analyst time; false negatives allow 
   attacks. Achieved 93%+ F1-score with 98%+ ROC-AUC, indicating excellent 
   discrimination capability."

Q: "How would you scale this to 1000 clients?"
A: "FedAvg aggregation is O(1) regardless of client count. Main bottleneck 
   would be server bandwidth/compute. Could implement: asynchronous aggregation 
   (FedAsync), hierarchical federated learning (edge servers), or compression 
   (weight quantization) to handle thousands of clients efficiently."

Q: "How does this compare to centralized training?"
A: "Centralized would achieve similar accuracy (94%+) but requires centralizing 
   all traffic data, creating privacy/compliance risks, single point of failure, 
   and potential regulatory issues. Federated maintains 94% accuracy while 
   distributing these risks and respecting data locality."
